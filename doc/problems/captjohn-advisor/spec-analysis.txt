REPRESENTATION AND AUTHORING APPROACH
  Path B (hand-authored, no include-tech), problem-type planning.
  State: each token's cell and the reverse cell->token occupant table (grass
    = no occupant); the next token to place (exists only during placement);
    John's cell and the cells he has left (route). Crew counted as visited
    when left or currently occupied by John.
  Phase fact dropped (user accepted 2026-10-11): place action requires a
    next token, move action requires none; the final placement also tests
    the grass clues, so every completed layout is the placement goal; goal
    states are not expanded under backtracking (ww-backtracker.lisp
    explore-choice-bt / accept-goal-bt), so no moves occur in the placement
    run regardless of cutoff. Route run starts from the saved layout, which
    has no next token.
  Cost 1 per action. File settings (placement): planning, every, tree,
    depth cutoff = token count. Route settings and *algorithm* via REPL.
  Clues: one line per clue over reusable relation queries (user chose
    2026-10-11); a data-driven clue interpreter rejected as excess machinery.
  Section 2 (accepted 2026-10-11, written):
    Cells R<row>C<col> generated from *captjohn-grid-size*; row 1 top,
      column 1 left. Token kinds as types (captain, vessel, guard, crew);
      clue lines quantify over kinds.
    Layout = one bijective relation (located $token $cell) serving both the
      token->cell and cell->occupant lookups (replaces the two relations
      described in section 1; same content). Grass = no occupant.
    John's current cell is a separate fact (john-cell), so the layout stays
      fixed during the route and John may stand on a crew or ship cell
      without a second occupant.
    Static, derived by init actions: cell-position (row, col, row-major
      index); vertical, diagonal, king neighbor lists. Authored: placement
      order (next-in-order), same-kind ordering (after-same-kind), fixed
      grass (clue 7).
    clue-broken? : one line per clue, each broken only when its tokens are
      placed and its test fails; clues 4 and 6 only when no next token.
      Order-independent, so D4 can change without editing clues.
    Fluent names are types (ww-installer.lisp normalize-fluent-spec strips
      the $; ww-validator.lisp check-proposition checks values against it):
      cell-position uses $coordinate $coordinate $fixnum, neighbor lists
      $list (user caught the undeclared $index/$cells, 2026-10-11).
    Engine detail relied on: the standard parameter header drops tuples with
      equal values (ww-support.lisp get-pre-lambda-arg-lists), so the
      row x column init action uses the product header; multi-variable
      guard quantifiers (standard) give ordered distinct pairs.
