Crelay-Topo Backward Analysis -- Tree
=====================================

Started 2026-09-17.  Companion files: Backward-Justification.txt (why each
node holds), Backward-Rules-Facts.txt (heuristic, rules, facts, lemmas,
nogoods, symmetries cited by label).  Supersedes the narrative draft in
Working-Backwards-from-Goal.txt.

Node format
-----------
  <label>  [<kind>] <alias>  <status>  f=<n>  <cites>
      <content, one condition or clause per line>

Kinds
  S   state node: open conditions still to be achieved (unordered set)
  A   action node: the action (schema) that achieves a chosen condition
  P   parameter node: binding or grouping of an action's arguments

Status
  A   active: on the path currently being expanded
  O   open: not yet expanded
  X   excluded at creation by a cheap local test (cite R/F/T/G/Y)
  R   refuted after expansion (cite the refuting child or nogood)
  D   done: conditions hold in the initial state or a validated checkpoint

Variables
  ?agent-loc    agent1's location, in the plate room {L16 L17 L18} unless said
  ?from-loc     the location a walk starts from
  ?cargo        a holdable object (wouldwork type CARGO)
  ?cargo-loc    that object's location
  ?plate        the plate whose occupancy is being achieved
  ?other-plate  one of the remaining plates
  ?occ6 ?occ7 ?occ8   the occupants of plate6, plate7, plate8

Conventions
  - Labels are permanent; new siblings take the next free number.
  - Each S node also gets a short alias Nn, numbered in creation order.
  - Each non-X node carries f = depth + h (heuristic H1 in
    Backward-Rules-Facts.txt).  The next node expanded is the open node
    with the smallest f; ties go to fewer ghost-dependent conditions, then
    fewer gate conditions, then greater role consolidation (H2).  The
    validated solution is used only as a sanity check, never to choose.
    Nothing is pruned on f, since any solution is acceptable, and a
    landmark shown wrong by later analysis is corrected in H1.
    Since the max(h) pass of 2026-09-17 (H4), h >= 18 for every node
    (gate8 measured at 18 or more) and h >= 19 for every node placing
    agent1 inside the plate region (the crossing walk is one more).
    Since 2026-09-18 K15's +8 is in the base (every solution needs a
    ghost outside the west strip, T21) and K17's +1 (plate3 occupied
    for gate4) is charged everywhere, and a node's f no longer says
    whether it needs a ghost -- every node does.
    Since 2026-09-18 (later) K14's live +2 is in the base as well: no
    ghost ever reaches L14 (T23), so agent1 throws switch2 and walks
    back.  Base h is 29.  The same lemma refuted every node that put
    agent1* at L14, L15, L21 or in the plate room, and T24 (the census
    with ghost keepers counted) refuted the L14 states; those nodes
    carry R with a REFUTED line.  Test 13 (2026-09-18) then raised K10
    to +4: the tray subtree under 1.1.1.1.1.1.2.1.1.3 rose by 2.
    Ghost occupants of gate9 plates are
    still possible, but only as copies inherited at a fork (F18, T18):
    the live original must be on the plate when START-RECORDER runs.
  - A node whose children are all X or R becomes R.
  - Open conditions within an S node are unordered; a child fixes an order
    only when ordering matters (resource release, gate closure).
  - An S node's open conditions are kept complete: jointly sufficient for
    the remaining actions below it to succeed (required by lemma T4).
  - Equivalent cases are grouped into one P node until a later constraint
    distinguishes them (see symmetries in Backward-Rules-Facts.txt).
    When an action's parameters need no split, their domains ride on the
    A node and its S child follows directly, without a P node.
  - Every new child is tested immediately against the node's constraints,
    lemmas (T), nogoods (G), and the ghost-playability check (P1);
    failures are marked X on creation.
