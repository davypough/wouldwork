REPRESENTATION AND AUTHORING APPROACH
  Path B, planning, graph search (R3).
  Squares: only playing-color squares exist as objects, named RrCc (max 50 on 10x10).
  Fox: (fox-at $square), one value; absent until the fox chooses its start (section 2).
  Geese: named objects GOOSEc, c = starting column; (goose-at $goose $square :bijective).
    Direct representation; interchangeability deferred to enhancements (symmetry pruning).
  Turn: nullary (geese-to-move), true on the geese's turn (nullary dynamic relations
    are supported: ww-installer.lisp signature for nullary relations; used in
    test/engine/problem-engine-query-update-parameter-tests.lisp).
  Not stored: square emptiness, trapped fox (computed when needed).
  Settings (defparameter, edit and restage): *n* (3..10; lower limit set by user 2026-10-18), *plays-r1c1-color* (T/NIL),
    *fox-first* (T/NIL).
  Cost unit: every action costs 1 (one ply; a pass is a ply, as counted by D2).
  Left to the REPL: *depth-cutoff*, *threads*, *solution-type* (run choices).
  square-name helper kept (used in type generation and neighbor lists), as in
    problem-captjohn-advisor.lisp.

  2. Board, pieces and starting position: proposed, agreed and written 2026-10-18.
     Static: square-position> (row, col), fox-steps (4 diagonals on board),
     goose-steps (forward diagonals; edge column 1, row n none), all set by init actions
     from the settings (no hand-authored board facts). Geese start on row 1 via
     initialize-geese; fox absent; turn unset.
     User confirmed 2026-10-18: the fox chooses its start square before the first move,
     also when the geese move first. Implemented in section 3 as a place-fox action
     (first step of every game; sets the next turn from *fox-first*; costs 1 step, a
     uniform offset that does not change which path is shortest).
     Open for staging: init action asserting the dynamic goose-at facts (not declared
     derived) -- confirm at first staging; whether define-init may be omitted.
  3. Actions: proposed, agreed and written 2026-10-18 (all cost 1).
     place-fox: fox absent; each row-n square; sets geese-to-move iff *fox-first* is NIL.
     move-fox: fox's turn; each fox-steps neighbor with no goose; then geese' turn.
       No legal move -> no successor (trap = dead end, geese win). Fox cannot pass.
     move-goose: geese' turn, per goose; each goose-steps neighbor holding neither a
       goose nor the fox; then fox's turn.
     pass-geese: geese' turn and not geese-can-move?; then fox's turn. Kept separate
       from move-goose (a combined action has no clean description for a pass); the
       two-part target test is repeated in geese-can-move?.
     Section 1 revisited: goose-at declared (goose-at $goose $square :bijective) so
       square occupancy is one lookup; engine rejects two geese on one square.
       Symmetry pruning compatibility with the bijective relation: confirmed 2026-10-18
       (see enhancements).
  4. Goal: proposed, agreed and written 2026-10-18: fox on a row-1 square (via
     square-position>). Geese win has no goal: trapped fox = no successor.
     A found path in this free version shows only that the fox can reach row 1 under
     free play; forced-win claims belong to the strategy-check variant.
     A duplicate define-goal (same code, different comment) was found at the end of
     the file during staging (goal installed twice); the second copy was removed.
  Basic-model review: pending (user).
  Resolved at staging: an init action may assert the dynamic goose-at facts (not
    declared derived); define-init may be omitted.

ENHANCEMENTS FOR THE LARGER FAMILY (first view, each to be discussed)
  - Geese interchangeable: symmetry pruning. IMPLEMENTED and enabled 2026-10-18
    ((ww-set *symmetry-pruning* t) in the spec settings).
    Growth issue: up to G! name permutations of the same goose arrangement (10x10: 120).
    Correctness: geese obey identical rules, the goal names no goose, answer identity
    (which side wins, path length) is independent of goose names; solutions still name
    the actual geese.
    Exercise (5x5, T, fox first, private copy, serial, min-length, cutoff 45):
      engine reports family (GOOSE5 GOOSE3 GOOSE1), strategy Global (closed-list
      canonical hashing); goal-referenced exclusion is the literal 1, not a goose.
      Merge check: two positions reached by different move orders with GOOSE1/GOOSE3
      swapped on R2C2/R3C3 give equal canonical forms; a different position does not.
      So the bijective goose-at is compatible (open issue closed).
      Search: 1,606 -> 1,482 states processed; minimum path 8 steps in both.
    Requirement carried to the strategy-check variant: the fixed geese rule must choose
      by squares, never by goose names (merged positions must share futures).
    Deferred (search advisor): benefit on 8x8 and 10x10, and overhead per state.
  - Static diagonal-neighbor lists per square (local choices): integrated in the basic
    model (fox-steps, goose-steps); no separate enhancement. Agreed 2026-10-18.
  - Shortcuts S1, S2 (earlier fox-win tests, sound per analysis D1): moved to the
    strategy-check variant, where they end a proven fox win sooner; in the free model
    they would only change what path length means. Agreed 2026-10-18.
  - Mirror symmetry of the fox's start square: moved to the strategy-check variant.
    Sound only for odd n (mirror keeps the playing color and the start position) and
    only if the fixed rule treats left and right alike. Agreed 2026-10-18.
  - Placeholder remaining-steps bound: IMPLEMENTED 2026-10-18 as min-steps-remaining?
    = fox row - 1 once placed, n before placement. Sound: each step moves the fox at
    most one row; reads stored facts only; pure function of the state.
    Exercise (4x4, T, fox first, private copy, 16 threads, min-length), with vs
    without the hook: start-state value 4; cutoff 33: 6 steps both (46 vs 232 states);
    cutoff 6: 6 steps both (32 vs 59); cutoff 5: no solution both (30 vs 44). Answers
    agree; the state counts show the hook ran.
    Deferred (search advisor): a stronger bound (e.g. counting interleaved geese
    turns) and its pruning value on larger boards.
  - Strategy-check variant (R2): design agreed 2026-10-18; written and staged 2026-10-18
    (status below the design).
    File: probs/problem-fox-geese-geese-check.lisp (same board, pieces, settings;
      no geese-to-move -- always the fox's turn).
    Each fox move asserts the fox step and the rule's geese reply together; placement
      includes the opening reply when the geese move first. Search branches only on
      fox choices (start square, moves).
    Draft geese rule (user: "looks good for a draft"), ranked, top move played:
      1. Keep the line closed: drop moves after which the fox, geese frozen, could walk
         to row 1, unless all moves do so.
      2. Close in: fewest squares the fox can walk to.
      3. Keep geese mobile: most geese with an open forward square.
      4. Tie-break by squares: goose farthest from the fox's column, then farthest
         behind (nearest row 1), then leftmost goose, then its leftmost target.
      5. Pass if no goose can move.
      Total and deterministic; chooses by squares only (symmetry-pruning compatible).
    Implementation: one query returning the chosen move or pass, with a helper giving
      the fox's walkable-square count and whether row 1 is reachable after a
      hypothetical goose move.
    Goal: fox win, extended with S1 and S2 (proven fox wins). A found solution is a
      counterexample line; an exhaustive search with none proves the rule wins the
      variant for every start square.
    Settings: graph, FIRST, depth cutoff from D2 in combined steps. (Symmetry pruning
      dropped 2026-10-19 with unnamed geese, below.)
    Mirror start squares: left out (the leftmost tie-break is not mirror-equivariant).
    Checks planned: rule-choice replays; 4x4 and 5x5 hand-checkable runs; 8x8 at the
      user's cutoff.
    Status 2026-10-18: file written (sections agreed one by one). Deviations from the
      design: mobility count in its own query open-geese?; remaining-steps bound omitted
      (S1/S2 can end a line sooner than fox row - 1, so the bound could cut a real
      counterexample; stronger sound bound is a search-advisor question).
    Staging (8x8, T, fox first, private copy): clean. Smoke check: start-position
      reply GOOSE1 R1C1->R2C2 for every fox start (every other move frees a row-1
      square the fox can reach); fox-walk? for that move = 26 squares, no row 1 (hand
      count agrees).
    Symmetry finding: staging reports no families. prune-inoperative-symmetry-groups
      keeps a family only if some action parameter ranges over it; here only the rule
      query iterates the geese. Searches stay sound, without merging renamed positions.
      User's decision: engine change in a separate session (project doc
      claude/symmetry-query-only-family-prompt.md), then resume here with pruning on.
    Resolved 2026-10-19 (engine session): engine change abandoned and fully reverted.
      Keeping a query-only family needs a check that every loop over the family is
      independent of visit order; applied to all families, that check also exposed
      never-checked loops in Talos code (no known wrong result), a much larger audit.
      Instead the variant now uses unnamed geese: (goose-on square) replaces the named
      geese and goose-at, so positions differing only in which goose is where are the
      same state, with no symmetry family or pruning needed (*symmetry-pruning* NIL).
      The rule, fox-walk?, open-geese? and goals S1/S2 range over goose squares; the
      reply is (from-square to-square); the step label shows $goose-from $goose-to.
      Scores unchanged (already by squares). Staging (8x8, T, fox first, private copy):
      clean, no families; start reply R1C1->R2C2 for every fox start; fox-walk? for
      that move = 26 squares, no row 1 (same as the named version).
  Deferred to search advisor (agreed 2026-10-18): whether a packed geese bit-board
    (geese interchangeable by construction) beats named geese + symmetry pruning.
    Kept named squares/pieces: small positions (<= 6 facts), static neighbor lists

    Update 2026-10-19: the strategy-check variant now has unnamed geese (above); the
