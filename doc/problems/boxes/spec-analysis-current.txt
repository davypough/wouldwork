2. COMPLETE MODEL AND REQUIREMENT MAPPING

Objective: return one globally shortest sequence of unit pickup, placement and
gate-crossing actions. Tied optima need not all be returned. Anonymous instructions
identify agent, source/destination area, named plate or gate, and the carried box.

Given instance is preserved:
- agent1 starts in area1; box1 starts on ground in area1, box2 in area2.
- area1..area4, plate1..plate3, gate1..gate3 retain their given identities.
- gate1 separates area1/area2; gate2 area1/area3; gate3 area3/area4.
- plates1/2 are in area1; plate3 is in area3; plateN controls gateN.
- all plates/hands start empty, all gates closed. Goal is agent1 in area4.
These are the original twelve DEFINE-INIT facts; no apparatus or geometry added.

Sufficient changing state:
AGENT-AREA, LOOSE-BOXES for every area including zero, OCCUPIED plates, CARRYING.
The initial database has five entries: one agent area and four ground counts.
Gate openness is derived from occupancy of its sole controlling plate. Static
topology, controller indexes and crossing bounds do not enter the copied dynamic DB.

Requirement -> implementation -> evidence:
- Preserve objects/layout/wiring -> DEFINE-TYPES, twelve raw initial facts,
  GATE-SEPARATES/PLATE-AREA/CONTROLS -> source comparison; passing topology checks.
- One agent/capacity-one hands -> PICKUP requires not CARRYING; PLACE requires
  CARRYING -> four fixture tables include full-hands rejection and valid placement.
- Unlimited ground storage -> nonnegative per-area count, one anonymous pickup
  for any positive pile -> two-box pile fixture yields one pickup and count 2 -> 1.
- Local handling and capacity-one plates -> local static plate list; occupied-only
  pickup/empty-only placement -> remote/occupied-target rejection and all three
  independent placement alternatives in the fixture checks.
- Open incident crossings in either direction, carrying permitted -> local gate
  list, GATE-OPEN?, OPPOSITE-AREA -> supplied basic path crosses gate1 both ways;
  carrying/closed/nonincident cases are also covered by the focused fixtures.
- Supporting box remains when crossing; recovery immediately closes its gate ->
  crossing writes only AGENT-AREA; plate pickup retracts OCCUPIED -> displayed
  basic path and fixture gate-status comparisons against original wiring.
- Box conservation -> initial count derivation and BOX-ARRANGEMENT-VALID?; each
  pickup/placement subtracts one at source and adds one at destination -> algebraic
  argument, all displayed basic states, and every checked successor.
- Unit action counts and independent alternatives -> three DEFINE-ACTION costs 1,
  separate complete ASSERT blocks per alternative -> exact traces, unit duration,
  distinct child databases and unchanged parents in nine checked successors.
- Goal has no extra final box/carrying requirement -> direct
  (agent-area agent1 area4) -> source review and copied area4 goal/bound-zero check.
- Preserve cheaper arrivals -> GRAPH/MIN-LENGTH and strict smaller-depth reopen
  paths in current engine -> source review, supplied optimum retained, and eight
  passing isolated serial/worker arrival cases including distinct plate allocations.

Capacities follow structurally: pickup changes empty hands to carrying; placement
changes carrying to empty and can occupy only an empty plate. Counts cannot become
negative because ground pickup requires a positive count. Every retained transfer
preserves loose counts + occupied plates + carried indicator. Crossing changes
only the agent's area. No timing/history/coordinates are needed under the agreed
local, sequential, free-within-area movement rules.

Reductions and their premises:
R1 omits agent plate visits and standing-on-plate state. A lone agent cannot exploit
its own temporary gate activation while crossing a separate gate; local handling
does not need an open gate. Area goal, immediate closure and unit costs justify
removing such visits from an optimum, while preserving the upstream physical ability.
R2 represents interchangeable boxes as counts/occupancy, eliminating only label
permutations. Distinct area/plate allocations remain distinct; anonymous output
needs no physical-name decoder. Spatial symmetry is not assumed.
R3 removes positive-cost cycles in identical complete arrangements. Their future
choices are identical, so deleting a cycle improves length. Cross-route sharing
must retain the cheaper arrival; see the passing focused execution check below.
Reopen these arguments if agents, timing, capacities, locality, costs, output
identity or goal mechanics change. Increasing objects/connections alone under the
same rules does not invalidate them.

3. ENHANCEMENTS, COSTS AND ENGINE CONTRACTS

Counts and combined actions are part of the basic model. PICKUP/PLACE share common
tests/lookups and emit each ground/plate alternative through a separate ASSERT.
Each legal successor still copies state. Counts remove box-label multiplicity;
they need not use less storage when areas greatly outnumber boxes.

Static indexes:
AREA-PLATES/AREA-GATES are built once in declared object order. CONTROLS is bijective
with both fluent positions, so CONTROLLING-PLATE uses the engine's gate-keyed inverse
index. GATE-OPEN? reads just that controller. Actions iterate only local candidates.
Setup/storage O(areas + plates + gates); incidence has two references per gate.
Lists are shared read-only in search, with no new dynamic entries. Worker snapshots
may copy static data; no parallel speedup or measured allocation saving is claimed.

All-open crossing bound:
A temporary neighbor map from validated endpoints feeds breadth-first layers from
goal area4. Each area is discovered once. AREA-CROSSING-BOUND stores exact all-open
crossing distance for reachable areas, explicitly zero for disconnected components.
Supplied values are area1 2, area2 3, area3 1, area4 0. MIN-STEPS-REMAINING? makes two
indexed reads: actual agent area, then its static bound. No ordering hook is added.
Any completion has at least this many crossings; box handling/gate restrictions
cannot lower its action count. Zero is a valid lower bound for an impossible
disconnected completion, although it provides no extra pruning there.
Setup O(areas + gates); temporary storage O(areas + gates), extra persistent static
storage O(areas), constant per-evaluation lookup. At cutoff zero it helps after
an incumbent exists. Current engine rejects depth + bound > positive cutoff, or
>= incumbent depth for MIN-LENGTH. This preserves one minimum solution.

Initialization/translation:
Raw checks establish complete ground-start input, one agent, valid distinct gate
endpoints, exactly one plate per gate and vice versa, and plate endpoint locality.
Engine validation handles types and duplicate fluent keys. Init order is topology,
crossing bounds, box counts; static BINDs use symbolic tables, then the engine's
final integer conversion publishes the derived static facts before query use.
Count initialization uses the compiled GROUND-COUNT query for integer-keyed dynamic
reads. DSL query calls stay in translated positions, outside opaque CL macros.
The direct goal saves goal-test work, not dynamic state-copy contents: static goal
data would not have been copied either. If changing goal datum, update area4 in
both bound derivation and direct goal.
The authored input format starts boxes on ground. An instance starting with a
box on a plate or in hand needs an explicit initialization-format review, even
though the changing-state representation can express those arrangements.
